2026-07-04: end-state design written at `isaac-paperclip/docs/ISAAC_OMEGA.md`
(seven closures; thesis: "a symbol is the graduation ceremony of a
statistic"). The first draft said "not a chatbot, science engine" — the owner
overturned BOTH the same day:

1. **It should be a chatbot** — "that's how people will also interface with
   it eventually." Resolution: conversation is the interface tier; speech is
   gated English (every sentence backed by net objects or an honest shrug);
   LLMs licensed as mouth-and-ears with a faithfulness null, never the
   verdict tier.
2. **More than discovery — an engineer** — "find information, find issues,
   and be able to fix and resolve them logically and explicitly. R&D, not so
   much science." Resolution: Closure 6 — specs as expectations, faults as
   signed effect entities, root cause via DO-probes, repair = laws run
   backward through solve(), fixes verified against their own null, failed
   fixes kept as wisdom.

**Why:** I framed Isaac as a pure science instrument; the owner's vision is a
usable colleague — the mission ([[lost-einsteins-mission]]) needs the
interface and the fixing, not just the finding.

**How to apply:** when designing forward, weight the engineer loop and the
conversational surface as first-class targets, not afterthoughts; never
reintroduce the "not a chatbot" frame. The doc keeps the overturned position
wearing its defeat ([[wisdom-laws]] applied to design docs too).
