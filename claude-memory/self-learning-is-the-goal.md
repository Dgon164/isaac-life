**Owner, 2026-07-13 (during the interpreter-segment discussion), verbatim
intent:** "the goal is a system that can self learn. and self learning
includes learning improved methods. thats it. it needs to learn
structures, uses, now its learning about goals and direction, and other
things."

The frame that snaps everything together:
- **structures** = what things are (the ladder: vocab, ideas, groups)
- **uses** = what things do (use-grounding, operators, affordances)
- **goals/direction** = the motivation material (new territory)
- **improved methods** = his own tools are learnable content too —
  authored organs (e.g. discover()) become CALLABLE NODES with doors +
  use-receipts; when one fails somewhere, his own creation duels it and
  supersedes THAT PART only ([[wisdom-laws]] applied to organs).
  "Something is better than nothing. Never let perfect get in the way
  of good enough." — no demolish-and-regrow.

**Reinforced 2026-07-15 (owner, approving the data-ops/interpreter work
order):** "everything we build needs to be a tool in the chain for
isaac to use so if something better comes later he can supersede this."
Applies to EVERY new build (floor organ, commonality miner, audit face,
storage roads): built as a supersedable tool in his chain, never welded
in.

**Why:** this is the evaluation yardstick for the interpreter segment
(owner rejected grander framings — regrow-from-scratch, sheet
ceremony). First target supersession: discover() loses on plain sums
(the measured blind spot); a minted linear candidate beats it exactly
there and nowhere else.
**How to apply:** judge every piece of the interpreter/Gate-6 work by
"does this let him learn structures, uses, goals, or better methods
himself?" — not by architectural elegance or prior-art novelty.
